# EduDSS — 10-Minute Technical Defense Script

Target: ~10 minutes, technical committee. Builds on the 5-minute script but goes deeper
into methodology, numbers, and defensible tradeoffs.

---

**[0:00–1:00] Framing**

"EduDSS is a role-based academic Decision Support System covering Student, Lecturer, and
Admin views, built as a single Streamlit application with a clean service-layer
separation. I'll walk through the ML methodology, the RAG architecture, the governance
layer around model promotion, and then be explicit about what's real versus what's
architecture-only."

**[1:00–3:00] ML methodology**

"For classification I implemented four algorithms — Logistic Regression, Random Forest,
XGBoost, and LightGBM — each tuned via GridSearchCV with 5-fold cross-validation, except
XGBoost's classifier, which uses fixed parameters due to a documented crash that happens
when rare classes become non-contiguous across CV folds — that's a disclosed exception,
not an oversight. For regression, the same four-algorithm structure exists with exact
grid sizes I can give precisely: Random Forest is 12 combinations / 60 fits, XGBoost and
LightGBM are each 18 combinations / 90 fits, Linear Regression has no hyperparameters.

Anti-leakage discipline is enforced structurally, not just by convention: the
train/test split happens before any preprocessing step. Imputation, scaling, encoding,
and SMOTE oversampling are all wrapped inside a single pipeline object that only gets
fit inside GridSearchCV's internal training folds — the test set never touches a fitted
preprocessing step. On top of that, there's a separate target-leakage filter that removes
any feature too strongly correlated with the target before training even starts."

**[3:00–4:00] Why regression R² looks high on the sample data**

"If you look at the regression numbers on the bundled sample dataset, R² is very high —
and I want to explain exactly why, because it's not what it might look like. The sample
dataset's target variable is generated by a known linear formula over the other synthetic
columns, plus a small noise term, then clamped to a tight band. That's a property of how
the demo data was constructed, not evidence that the anti-leakage pipeline failed — those
are two separate, verifiable things, and I checked both independently in the source code
this cycle."

**[4:00–6:00] Clustering, SHAP, Diagnosis, Learning Plan**

"K-Means clustering groups students by behavioral and academic similarity, with k chosen
via elbow and silhouette analysis — this is unsupervised; it does not predict outcomes.
SHAP gives per-feature contribution values for individual predictions, using Shapley
values from cooperative game theory — this explains what the trained model weighted, not
a causal claim about the real world.

The Diagnosis Engine is deliberately not machine learning — it's explicit, auditable
threshold logic over the student's profile, so every diagnosis can be traced to a
specific rule. The Learning Plan generator is the same philosophy: a rule-based/heuristic
structure builder. The language model's only role there is narration — turning the
already-decided plan into natural, encouraging language for the student. This separation
was a deliberate design choice for auditability."

**[6:00–8:00] RAG and AI Advisor**

"The AI Advisor layer is Retrieval-Augmented Generation. Documents — course material,
lecture uploads — get chunked and embedded, stored in a vector index. A query gets
embedded the same way, compared by cosine similarity, and only chunks above both an
absolute confidence floor and a relative-to-top-hit threshold are kept. If nothing clears
that bar, the system returns an honest 'no relevant evidence' response instead of forcing
an answer. What actually reaches the language model is a grounded prompt built from those
retrieved chunks, and the response carries a citation back to the real source. I verified
this whole loop live this cycle: uploaded a document, asked a question, and got back a
verbatim quoted citation traceable to that exact file.

There's also governance around model lifecycle: a Model Registry with
candidate/production/archived states. Promotion to production is Admin-gated only — I
verified in source that the real training call site explicitly passes `auto_promote=False`,
so even though the system computes an internal 'is this the best model so far' flag,
it never auto-promotes."

**[8:00–9:00] Honest boundaries**

"Two things I want to be precise about, because they're the most likely to come up. First:
there is no live external LMS or CMS integration. The repository pattern is there — a
clean interface ready for a real connector — but the current implementation of that
interface delegates internally to demo data; no network call reaches an actual LMS
platform. Second: there's a PostgreSQL-plus-pgvector backend with a real connection test
and a real schema — pgvector extension, HNSW index — but its four CRUD operations are
stub implementations with no actual SQL execution, and it's never activated in this
deployment. The system's real, active vector store is a simpler file-based implementation."

**[9:00–10:00] Closing**

"426 tests pass — 403 unit/integration plus 23 real-browser end-to-end tests — and every
fix made during the audit phase of this project has a corresponding regression test. I
tracked 26 issues total across the audit; 22 are fixed, 4 are deliberately left open with
documented reasons, and none of the open ones are severity-blocking. I'm ready for
questions on any layer — ML methodology, the RAG pipeline, or the honesty tradeoffs I just
walked through."
